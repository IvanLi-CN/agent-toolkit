# DST helper contract

## Entrypoints and side effects

Run `bun scripts/dst_snapshot.ts` or `bun scripts/dst_mods_from_modoverrides.ts` relative to this Skill, or use an absolute path through a source directory link from another working directory. Both accept `--help` and fail with exit 2 and `error:` on stderr for invalid arguments. Remote host/user/cluster values come only from explicit arguments or the documented environment. Unsupported command options, shards, unsafe target strings and missing required remote configuration fail before SSH. The tools perform no restart, update, mod change, permission change, installation or deployment.

Snapshot options are `--host`, `--user`, `--out`, `--local-dir`, `--no-local`, `--no-remote`. The default report is a timestamped file in the OS temporary directory. The output parent must exist; an existing output is replaced. Local collection records up to 200 root entries, log presence and up to 100 cluster paths with token/config existence and shard presence. It supports `Cluster_*` directly under the client directory or beneath an account directory. Directory names and paths are operator data; redact them before sharing externally. Log/config contents are omitted, including `client_log.txt`, `cluster.ini` and token files. A missing or unreadable local directory produces a partial report rather than stopping remote collection.

Remote snapshots use native Shell to observe identity, resources, service active state, listening ports, process names, known runbook/helper paths, backup names, cluster/shard metadata and conventional binary paths. The remote collector requires POSIX `sh`, `dd`, `wc`, `tr` and `head`; optional probe commands are omitted when unavailable. The mod byte cap uses `dd if=... bs=1 count=1048577`, while snapshot line caps use POSIX `head -n`, so no GNU-only byte option is required. Process arguments, service status/journal content, logs, tokens, configuration contents and runbook contents are excluded. Backup listings are capped at 120 lines, cluster inspection at 100 directories, and native command output at the stated per-command limits. The collector is metadata observation, not a general recursive binary search. SSH failure or timeout produces a partial snapshot warning, with exit 0 if the report was written; it is not a successful remote observation.

Mod options are `--host`, `--user`, `--cluster`, `--shard Master|Caves|both` (default both; lowercase single-shard names are accepted), and `--cluster-dir PATH`. The local selector takes precedence over remote configuration and reads only selected `Master/modoverrides.lua` and `Caves/modoverrides.lua`. A missing cluster fails; a missing shard file is reported without inventing state or comparing unavailable shards. Remote mode requires a configured host, user and safe single-component cluster name. Shell sends only the selected files using the private `DSTMODS1` framing (one shard header with byte count or `missing`, followed by exactly the declared bytes). Local Bun validates framing and supported syntax, then emits counts and numerically sorted IDs for true/false/unknown states. For two available shards, it reports set differences for enabled and disabled IDs separately. Malformed configuration/transport or failed SSH exits 2 without a partial mod summary or raw source/stderr.

Each mod file is capped at 1048576 bytes; SSH stdout and stderr are drained concurrently with independent 3145728-byte caps and a 15-second whole-command timeout. Overflow terminates the SSH child and fails the collection. Raw SSH stderr is discarded, since a server banner/error can contain secrets. The local report error contains only the transport outcome. SSH uses `BatchMode=yes`, `StrictHostKeyChecking=yes` and `ConnectTimeout=5`; an unknown key, password/2FA challenge or unavailable key must be resolved manually before retrying. No live SSH test is implied by mock results.

## Supported mod syntax

The parser accepts `return` followed by one Lua table constructor, optional trailing semicolon, string or numeric bracket keys, identifier keys, list fields, comma/semicolon separators, nested tables to depth 64, decimal numbers (including exponent), booleans, nil, symbolic identifiers, single/double quoted strings, long bracket strings, line comments and long bracket comments. Short strings support escaped quotes, backslash, `n`, `r`, and `t`; other escapes, functions/calls, operators, executable statements, variable declarations and arbitrary Lua programs are unsupported and fail closed. Duplicate keys are rejected rather than interpreted. Configurations outside this subset require manual inspection, not execution.

Only root keys exactly matching `workshop-<digits>` become mod entries. Each must contain a table. Only that entry's immediate `enabled=true` or `enabled=false` establishes its state; absent, nil, symbolic and other values are `unknown`. Nested `configuration_options.enabled`, strings and comments never change the top-level state. Strings/configuration values are never included in summaries or parse-error diagnostics. IDs remain decimal strings, including values larger than JavaScript's safe integer range. Configuration is tokenized and structurally parsed without invoking Lua, a game server or a shell evaluator.

## Validation and evidence limits

Run `bun test ./tests/dst_helpers.test.ts` from this Skill. HELPERS-03 uses temporary files, fake SSH and isolated native Shell to check local/remote selection, secrets, limits, failed SSH, missing clusters/shards, reports and differences. HELPERS-04 covers nesting, comments/strings, unknown state and malformed/unsupported input without executing it. Fake SSH is transport simulation; executing the retained Shell against a temporary home is isolated native OS evidence. Neither is a real deployment observation. Actual server access, game readiness and deployment behavior remain unavailable until explicitly observed on the configured target.
